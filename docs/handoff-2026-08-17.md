## 2. FIXES DE HOY

1. **Reescritura de regla de accesos en prompt**  
   `apps/whatsapp_bot_v4/ai/prompts.py:16-17`  
   **Por qué:** El modelo interpretaba "En pisos superiores, acceso solo ascensor o escaleras" como regla universal que debía aplicar siempre (hallucination). Reescrito a "access solo se extrae si el cliente lo menciona explícitamente. Única excepción: piso 1 implica NOT_APPLICABLE en ese extremo." Con ejemplo negativo explícito: "de 2do piso a 4to piso" no extrae access.

2. **Implementación de validación anti-hallucination en layer de servicio**  
   `apps/whatsapp_bot_v4/services/conversation_service.py:404-434` (`_guard_access_hallucination()`)  
   **Por qué:** Prompt reescrito no alcanza; el modelo sigue inventando accesos en casos edge. Añadida validación que descarta `origin_access` y `destination_access` si el mensaje no contiene keywords de acceso (`ascensor`, `escalera`, `elevador`, `gradas`, `escaleras`). Log: `bot_v4_access_hallucination`. Llamada DESPUÉS de `_guard_new_quote()` en `process_turn()`.

3. **Suite completa de tests para anti-hallucination**  
   `apps/whatsapp_bot_v4/tests/test_access_hallucination.py` (nueva)  
   **Por qué:** Validar que la regla de accesos NO descarta valores legítimos pero SÍ descarta hallucinations. Cuatro tests: (1) sin mención → ambos access null, (2) piso 1 → origin NOT_APPLICABLE, (3) escaleras explícitas → extrae, (4) ascensor explícito → no hallucination.

4. **Reparación de 7 tests fallidos por validación anti-hallucination**  
   `apps/whatsapp_bot_v4/tests/test_quote_flow.py` (6 cambios) + `test_meta_adapter.py` (1 cambio)  
   **Por qué:** Tests usaban ScriptedAgent que emitía access values sin que el customer_message mencionara keywords de acceso. Estrategia: actualizar mensajes para que sean realistas. Ejemplos:
   - `"todo"` → `"de Surco a Miraflores, del piso 1 sin ascensor al 2 con escaleras, 1 cama"`
   - `"datos completos"` → `"de Surco a Cercado de Lima, del piso 1 al 2 por escaleras, cama cocina escritorio"`
   - `meta_payload()` → `meta_payload(text="de Surco a Miraflores, del piso 1 al 2 con escaleras, 1 cama")`
   - `"necesito otra mudanza, de Barranco a Lince"` → `"necesito otra mudanza, de Barranco a Lince sin ascensor"`

5. **Validación de customer_question en respuesta**  
   `apps/whatsapp_bot_v4/services/conversation_service.py:307`  
   **Por qué:** Bug reportado día 1: cuando cliente responde pregunta, la respuesta se descartaba si había otros campos pendientes. Añadida verificación: si `customer_question.asked=True`, la respuesta NO se descarta solo por mezcla de campos. Primero recorta a grupo lógico con prioridad (ruta > pisos > accesos > items), luego valida que `requested_fields` esté en `missing`.

## 4. PENDIENTES ANOTADOS

- [ ] **business_context expandido:** Agregar servicios adicionales (embalaje, tiempos de atención, opciones de pago) al contexto que recibe el modelo. Impacto: respuestas más comercialmente informadas sin hardcoding.

- [ ] **Limpieza de heurística '"?" in reply':** La validación de response usa `"?" in output.reply` para detectar preguntas. Frágil si modelo emite "¿" o "?" en contexto no-pregunta. Considerar tokenización o análisis más robusto.

- [ ] **Unificar zonas horarias en logs:** Logs mezclados entre UTC (+00:00) y local. Definir policy: todo UTC o todo local, aplicar conversamente.

- [ ] **Alertas para estado='error':** Cuando un `MensajeWhatsApp` queda con `estado='error'`, no hay notificación. Implementar alert (Slack/log crítico) para no perder entregas silenciosas.

- [ ] **Timeout de COLLECTING (parcialmente implementado):** Configuración `WHATSAPP_BOT_COLLECTING_TIMEOUT_HOURS=6` existe en settings pero código que lo usa fue removido. Si se reintroduce, requiere test infrastructure robusta (no debe fallar por time alone).

- [ ] **Caso ambiguo: accesos con un solo extremo mencionado**  
  Ej: `"de Barranco a Lince sin ascensor"` — ¿sin ascensor es origen o destino?  
  Hoy: se descarta todo. Considerar heurística: si hay un solo acceso, asignar al destino (destino suele ser el "problema" arquitectónico).
